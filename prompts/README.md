# 提示词文件说明

本文件夹包含所有用于LLM交互的提示词模板。这些提示词从代码中分离出来，便于维护和修改。

## 文件列表

### 1. `determine_keyword_operator.txt`
用于判断关键词组合方式（AND/OR）的提示词。

**使用场景**：当用户提供多个关键词时，判断应该使用交集（AND）还是并集（OR）来组合搜索。

**变量**：
- `{user_input}`: 用户的原始输入
- `{keywords}`: 关键词列表

**示例**：
```
用户输入："找关于生信和AI的文献"
关键词：["bioinformatics", "artificial intelligence"]
→ 判断结果：AND（需要同时包含两个关键词）
```

### 2. `parse_user_request.txt`
用于解析用户自然语言需求的提示词。

**使用场景**：将用户的自然语言输入解析为结构化的搜索参数（关键词、日期范围、邮箱等）。

**变量**：
- `{user_input}`: 用户的原始输入
- `{current_date}`: 当前日期（格式：YYYY年MM月DD日）

**输出格式**：JSON格式，包含以下字段：
- `keywords`: 搜索关键词列表
- `keyword_operator`: "AND" 或 "OR"
- `days_back`: 最近N天（整数或null）
- `min_date`: 开始日期（YYYY-MM-DD格式或null）
- `max_date`: 结束日期（YYYY-MM-DD格式或null）
- `to_email`: 收件人邮箱（字符串或null）
- `max_papers`: 最大论文数量（整数）
- `filter`: 过滤条件对象

### 3. `summarize_paper.txt`
用于生成单篇论文中文总结的提示词。

**使用场景**：为每篇论文生成简洁的中文总结。

**变量**：
- `{title}`: 论文标题
- `{abstract}`: 论文摘要（已截断至500字符）

**输出要求**：
- 2-3句话概括研究内容和主要发现
- 突出关键技术和方法
- 控制在100字以内
- 使用中文
- 不包含"总结"、"摘要"等前缀

### 4. `summarize_literature.txt`
用于生成文献列表总结报告的提示词。

**使用场景**：对多篇论文进行整体总结，生成研究趋势和热点分析。

**变量**：
- `{paper_count}`: 论文数量
- `{papers_text}`: 论文列表文本（包含标题、作者、期刊、年份、摘要等信息）

**输出要求**：
- 总结主要研究方向和热点
- 识别关键技术和方法
- 突出重要发现和趋势
- 控制在500字以内
- 使用中文

## 提示词格式

所有提示词文件使用Python的`str.format()`方法进行格式化。在提示词中使用`{变量名}`来标记需要替换的变量。

**注意**：
- 如果需要在提示词中显示字面的`{`或`}`，需要使用`{{`和`}}`进行转义
- 例如：`{{"keywords": ["keyword1"]}}` 会输出 `{"keywords": ["keyword1"]}`

## 修改提示词

1. 直接编辑对应的`.txt`文件
2. 保存文件后，代码会自动加载新的提示词
3. 无需重启程序（如果程序正在运行，需要重启才能生效）

## 提示词加载机制

代码中的`_load_prompt()`方法会：
1. 从`prompts/`文件夹中读取对应的`.txt`文件
2. 如果文件不存在或读取失败，会使用代码中的默认提示词（作为fallback）
3. 使用`str.format()`方法替换变量

## 最佳实践

1. **保持简洁**：提示词应该清晰、简洁，避免过于冗长
2. **明确要求**：明确说明输出格式和要求
3. **提供示例**：在提示词中包含示例，帮助LLM更好地理解需求
4. **版本控制**：将提示词文件纳入版本控制，便于追踪修改历史
5. **测试验证**：修改提示词后，建议进行测试以确保效果符合预期

## 故障排除

如果提示词加载失败：
1. 检查文件路径是否正确
2. 检查文件编码是否为UTF-8
3. 检查文件权限
4. 查看日志中的错误信息
5. 代码会自动fallback到默认提示词，不会导致程序崩溃
